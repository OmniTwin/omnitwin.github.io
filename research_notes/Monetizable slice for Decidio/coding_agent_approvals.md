Research method note: GitHub (github.com), code.claude.com and web-search summaries were reachable; pushary.com, producthunt.com, apps.apple.com, docs.cursor.com, forum.cursor.com, opencode.ai, developers.openai.com, news.ycombinator.com, reddit.com, dev.to, techradar.com and incidentdatabase.ai were not fetchable from this environment, and the web-search budget ran out part-way. ## KQ1. Which tools let a person approve/deny/get notified of agent actions remotely, what do they charge, and is there evidence anyone pays?

### Takeaway
Dozens of free hook-based bridges exist (ntfy, Telegram, iMessage, Slack), two vendors ship first-party phone approval for free with the subscription (Anthropic Remote Control, OpenAI Codex remote control), and only a handful of indie products charge: Pushary ($9.99/$19.99 per month), Forge Remote (free tier, Pro $9.99/mo or $99.99/yr) and Happy (free, with in-app purchases listed). I found no revenue or paying-customer numbers for any of them; the only hard traction signals are GitHub stars and app-store rating counts.

### Inferences
- The "approve my own prompt from my phone" segment has collapsed to free: both platform vendors ship it inside the subscription, and the best-known indie (Omnara) pivoted to a different business. Paid survivors (Pushary, Forge Remote) sell at $9.99/mo, i.e. consumer-utility pricing, and bundle extras (multi-agent, policies, audit trail) to stay relevant.
- No source gives subscriber counts, MRR or App Store rank for any paid tool; the absence of such claims after a year of launches suggests small revenue.
- Guards (dcg 6.2k, cc-safety-net 1.6k) have ~20-80x the stars of remote-approval hooks (73), i.e. developers want *blocking* of dangerous commands more than they want to be *asked*.

## KQ2. What have vendors shipped natively, and which pains remain after Remote Control and free hooks (cross-agent inbox, second-person approval, audit trail, cloud/background approvals, per-command policy)?

### Takeaway
Vendors have closed "operator approves own prompt from phone" (Claude, Codex) and "block dangerous commands" (ask/deny rules, auto-mode classifier, dcg/cc-safety-net), but they have deliberately *not* built asynchronous approval for unattended cloud runs (Claude routines run "without stopping for approval"; #44771 closed "not planned"), there is no cross-vendor inbox from any vendor, and the only vendor-side audit of permission decisions is OpenTelemetry events that are observability data, not a tamper-evident record.

### Cited Findings

**Claude Code native surface**
- Hooks: `PermissionRequest` fires "when a tool call needs a permission decision", output `decision.behavior: allow|deny` (exit code 2 is *not* honoured); `PreToolUse` returns `permissionDecision: allow|deny|ask|defer` plus `updatedInput`; hook types are `command`, `http` and `mcp_tool`, default timeout 600 s, and "a timed-out command, http, or mcp_tool hook does not block the call. Set `onFailure: "block"` if a stalled hook should gate it"; `Notification` hook matcher `permission_prompt` has "No decision control"; enterprise controls `allowManagedHooksOnly`, `allowedHttpHookUrls`, `httpHookAllowedEnvVars`; "Cloud sessions don't read your local ~/.claude/settings.json"; `$CLAUDE_CODE_REMOTE="true"` in cloud, `$CLAUDE_CODE_BRIDGE_SESSION_ID` set during Remote Control — [Hooks docs](https://code.claude.com/docs/en/hooks)
- Known hook blind spots: "#21460 [SECURITY] PreToolUse hooks not enforced on subagent tool calls" (closed 29 May 2026); "#23983 PermissionRequest hooks not triggered for subagent permission requests (Agent Teams)" (open); "#6305 Post/PreToolUse hooks not executing" — [issue search](https://github.com/anthropics/claude-code/issues?q=is%3Aissue+audit+log+tool+permission+decisions+sort%3Areactions-%2B1-desc)
- Permission modes: `default`, `acceptEdits`, `plan`, `auto` (classifier reviews actions; the built-in starting mode since v2.1.283), `dontAsk`, `bypassPermissions`; "Deny rules block in every mode, including bypassPermissions"; "Explicit ask rules still force a prompt" in auto mode; managed settings can `disableAutoMode` / `disableBypassPermissionsMode`; `rm -rf /`-style critical-path removals skip the classifier — [Permission modes](https://code.claude.com/docs/en/permission-modes)
- Audit: OpenTelemetry `claude_code.tool_decision` carries `decision: accept|reject` and `source: config|hook|user_permanent|user_temporary|user_reject|user_abort`; `tool_parameters` only with `OTEL_LOG_TOOL_DETAILS=1`; `config` does not say which rule matched; nothing about tamper evidence or retention; cloud sessions can export only if the collector domain is allow-listed — [Monitoring docs](https://code.claude.com/docs/en/monitoring-usage)
- Cloud sessions: permission mode is picked from a dropdown; "A session counts as inactive while it waits for you to approve an MCP connector tool call ... and it can expire during that wait"; Team/Enterprise sessions can be shared with "Team" visibility (view only, "their view doesn't update in real time"); Slack-launched sessions auto-shared — [Cloud docs](https://code.claude.com/docs/en/claude-code-on-the-web)
- Routines (scheduled/API/GitHub-triggered cloud runs, research preview): "there is no permission-mode picker, and the session runs shell commands ... and calls any connectors you include, all without stopping for approval"; "Claude can use every tool from an included connector, including writes, without asking"; "Routines belong to your individual claude.ai account. They are not shared with teammates" — [Routines docs](https://code.claude.com/docs/en/routines)
- Related open bugs on unattended runs (counts from search listing, unlabelled): #61015 "Scheduled routines fail every MCP call with 'MCP tool call requires approval'" (43, closed); #47180 "Cowork scheduled tasks ignore 'Always allow'" (39, open); #77817 "v2.1.206 broke unattended scheduled tasks; runs ignore permissions.defaultMode; no bulk control" (8) — [issue search](https://github.com/anthropics/claude-code/issues?q=is%3Aissue+%22permission%22+%28slack+OR+telegram+OR+webhook+OR+mobile%29+approve+sort%3Areactions-%2B1-desc)
- Claude Code in Slack (legacy, Pro/Max) and Claude Tag (Team/Enterprise): Slack starts cloud sessions and posts status/completion with "View Session" / "Create PR" buttons; no mid-run approval buttons are documented; legacy bot retired 5 Oct 2026 — [Slack docs](https://code.claude.com/docs/en/slack)
- Remote Control bugs: #52084 "approving permission from phone hangs Claude Code on host" (22 Apr 2026, closed as duplicate of #45942); #29214 "mobile app shows permission prompts despite --dangerously-skip-permissions" (open since 27 Feb 2026, ~32 comments, no maintainer reply, users posting an auto-approve `PermissionRequest` hook as workaround) — [#52084](https://github.com/anthropics/claude-code/issues/52084); [#29214](https://github.com/anthropics/claude-code/issues/29214)

**Existing-asset mapping for the reader**

- The reader's Slack/Teams routing answers #44771's "Send permission requests to Slack, email, or a webhook, and resume the agent once the user responds", which Anthropic closed as not planned.
- The reader's PII vault addresses the trust objection in #15922 ("I don't trust any third party apps ... proprietary code passing through non-first-party apps") and the OTel caveat that `tool_parameters` are only logged with `OTEL_LOG_TOOL_DETAILS=1`.

### Inferences
- Vendor roadmaps converge on *removing* prompts (Claude auto mode default since v2.1.283; Codex Auto; routines with no approval), not on routing them. Anything that must still be approved in an unattended run is therefore an orphan use case at both vendors.
- The lack of any team-visible, resumable approval for routines, combined with "Routines belong to your individual claude.ai account", means team governance of scheduled agents is currently impossible with first-party tooling.
- Hook reliability bugs (subagent bypass, Codex desktop updates disabling hooks, fail-open timeouts) mean any hook-based gate needs `onFailure: "block"` and an out-of-band audit to prove it ran.

## KQ3. Is there demand evidence specifically for a SECOND person (a teammate, not the operator) approving an agent's action?

### Takeaway
Weak-to-moderate: I found no GitHub issue or thread at any vendor explicitly asking "let my teammate/lead approve what my agent does", but the adjacent demand is real — async Slack approval for unattended agents (#44771), Happy's "multiplayer" sessions, quorum approvals in MCP-governance tools, per-risk-class approver routing in blog guidance, and a 0-star OSS project that built exactly the Slack-approver-plus-signed-log design.

### Cited Findings
- #44771 (Apr 2026, closed "not planned" by stale-bot, no maintainer reply) proposes "Async approval through external channels: Send permission requests to Slack, email, or a webhook, and resume the agent once the user responds" for scheduled agents; the only commenter promoted Pylon, "a self-hosted daemon ... that pauses on a Slack approval channel" — [#44771](https://github.com/anthropics/claude-code/issues/44771)
- Happy README: "Natively multiplayer ... Invite a colleague or a friend into the session"; teams "should use the desktop app" — [slopus/happy](https://github.com/slopus/happy)
- Preloop (open-source MCP governance) lists "team-based approvals with quorum requirements (Enterprise) and per-tool approval workflows with a full audit trail" (search summary) — [glama preloop](https://glama.ai/mcp/servers/@yconst/preloop/tree/b1f7e8e473267657c23069541b85272078fbe60e)
- agent-governance-plane (0 stars, Apache-2.0, 277 commits, author affiliated with a Claude Partner Network partner): "gates each tool call through a policy engine, and sends calls marked for review to a human approver in Slack. ## KQ4. What do incident stories say people wish they had, and did any product gain adoption after one?

### Takeaway
Reported incidents (DROP TABLE / mass UPDATE on production via MCP, `terraform destroy` with auto-approve, 48k files deleted by a sub-agent, 2.5 years of website data) consistently ask for the same three things — a hard confirmation step on destructive operations, guards the model cannot talk its way past, and the ability to see the blast radius (row counts, paths) before approving. The adoption response has gone to *blocking guards* (dcg 6.2k stars, cc-safety-net 1.6k stars, a Leanpub book titled "Claude Code Safety"), not to remote-approval tools.

### Cited Findings
- #13325 (7 Dec 2025, pre-2026; closed "not planned" by bot, no maintainer comment): Opus in `acceptEdits` mode ran a Supabase MCP `UPDATE ... SET topic_standardized = NULL` wiping ~55,000 rows "without asking"; reporter asks for guards that "Block DELETE, DROP, TRUNCATE, or UPDATE...SET NULL affecting more than 100 rows", "Require an explicit 'yes' confirmation that shows the row count", and "Make these guards impossible to override through model reasoning" — [#13325](https://github.com/anthropics/claude-code/issues/13325)

- #6608 "Claude Code ran rm -rf without permission" (Aug 2025, pre-2026, 23) — [issue search](https://github.com/anthropics/claude-code/issues?q=is%3Aissue+audit+log+tool+permission+decisions+sort%3Areactions-%2B1-desc)

### Inferences
- The incidents that reach the press involve *no* human in the loop (auto-approve / acceptEdits / sub-agents), so the product lesson is "force a gate on a narrow class of operations and show blast radius", not "notify the operator more". That favours a policy-plus-gate product over a notification product.

- Nobody cites a remote-approval product as having prevented or being adopted because of an incident; the dev.to vendor claim is the only "we added approvals because of destructive commands" story found.

## KQ5. What does nobody sell yet? Gap ratings (demand evidence / competitive gap)

### Takeaway
The open, monetizable gaps are (1) asynchronous, resumable approval for *cloud/background* agents routed to a chat tool, (2) a second-person/role-based approver with a signed receipt, and (3) a tamper-evident audit of agent permission decisions across vendors; phone-approval of one's own prompts and Bash destructive-command blocking are closed or contested by free tools.

### Cited Findings
Each gap below is rated on demand evidence (strong / moderate / weak) and competitive gap (open / contested / closed), with the supporting sources already cited above.

1. **Operator approves own prompt from phone** — Demand: strong (#15922 ~21 comments "We desperately need this!"; #60433; #29438; Codex #9224 52-thumbs comment; 10+ Telegram clones). Competitive: closed — Anthropic Remote Control and Codex remote control ship it free; Happy (24.2k stars) and claude-remote-approver cover the rest. [#15922](https://github.com/anthropics/claude-code/issues/15922); [Remote Control](https://code.claude.com/docs/en/remote-control); [#9224](https://github.com/openai/codex/issues/9224)
2. **Per-command destructive policy (block rm -rf, force-push, DROP)** — Demand: strong (dcg 6.2k, cc-safety-net 1.6k, #13325 asks for hard-coded guards). Competitive: closed for Bash (free OSS plus vendor deny rules, Codex execpolicy), contested for MCP/database writes where no popular guard exists. [dcg](https://github.com/Dicklesworthstone/destructive_command_guard); [#13325](https://github.com/anthropics/claude-code/issues/13325). Reader asset: destructive-ops policy in the SDK plus MCP tool annotations cover the MCP side.
3. **Approvals for cloud/background/scheduled agents (resume on decision)** — Demand: moderate-to-strong (#44771 closed not planned; #61015 43; #47180 39; #77817; Codex #23200 23 comments, no reply; Claude cloud sessions expire while waiting on an MCP approval). Competitive: open — routines run "without stopping for approval", Pylon is self-host-only with 16 stars, Pushary's blocking gate needs a local hook process. [#44771](https://github.com/anthropics/claude-code/issues/44771); [Routines](https://code.claude.com/docs/en/routines); [Cloud](https://code.claude.com/docs/en/claude-code-on-the-web). Reader asset: HTTP-callable gate API with long-poll status plus Slack/Teams routing is the missing piece; the open question is whether cloud sessions honour an `http` hook from a committed `.claude/settings.json` (inference, untested).
4. **Second-person / role-based approver** — Demand: weak-to-moderate (no direct feature request; adjacent asks in #44771, Preloop quorum, Copilot's human-approves-workflows default, routing-by-risk-class guidance). Competitive: open — only agent-governance-plane (0 stars) and Happy's view-only multiplayer touch it; no vendor offers teammate approval. [agent-governance-plane](https://github.com/jeremylongshore/agent-governance-plane); [slopus/happy](https://github.com/slopus/happy). Reader asset: routing to a named human by web/phone/Slack/Teams plus signed receipt covers this fully; the gap is distribution, not build.
5. **Tamper-evident audit of agent permission decisions (cross-vendor)** — Demand: moderate (Cursor forum request: decisions "not persisted in any queryable, exportable form"; Codex #28437 "audit receipts"; #59248 silent transcript deletion 59; enterprise `allowManagedHooksOnly` / `allow_managed_hooks_only` features show vendors expect policy enforcement). Competitive: contested — Pushary advertises "an audit trail", Claude emits OTel `tool_decision` events with `source` attribution, agent-governance-plane has a hash-chained log, but none is cross-vendor, hosted and tamper-evident together. [Monitoring](https://code.claude.com/docs/en/monitoring-usage); [#28437](https://github.com/openai/codex/issues/28437); [toolradar Pushary](https://toolradar.com/tools/pushary/pricing). Reader asset: signed receipt is the differentiator; PII vault addresses `tool_parameters` exposure.
6. **Cross-agent inbox (one queue for Claude Code, Codex, Cursor, Gemini, OpenCode)** — Demand: moderate (repowire 267 stars "durable human inbox"; termdeck "fleet board"; Pushary multi-agent; cc-safety-net supports 14 CLIs). Competitive: contested — Pushary ($9.99/$19.99), Happy, Forge Remote, repowire already span 2-5 agents; nobody spans cloud agents plus local agents plus MCP tools. [repowire](https://github.com/prassanna-ravishankar/repowire); [pushary](https://pushary.com/codex-notifications). Reader asset: hook plus MCP connector plus web inbox already spans Claude Code, Claude.ai and ChatGPT; adding Codex `PermissionRequest` and Gemini `BeforeTool` adapters would be cheap.
7. **Timeout-is-not-consent (expiring prompts default to the model's choice)** — Demand: strong (Codex #28969 ~197 thumbs-up, open; Claude #73125 fixed by making it opt-in). Competitive: contested — Anthropic fixed it; OpenAI has not; Remote Control forwarded non-permission dialogs expire after 5 minutes (`dialogExpiry`). [#28969](https://github.com/openai/codex/issues/28969); [#73125](https://github.com/anthropics/claude-code/issues/73125); [Remote Control](https://code.claude.com/docs/en/remote-control). Reader asset: one-time grants with long expiry and signed receipt directly address "a timeout should not count as human consent".
8. **Hook-reliability proof (did the gate actually run?)** — Demand: moderate (#21460 subagent bypass, #23983, Codex #21639 hooks silently disabled after update, #41979 fail-closed request). Competitive: open — no product attests that the gate ran; `onFailure: "block"` exists only in Claude Code. [Hooks](https://code.claude.com/docs/en/hooks); [Codex hook issues](https://github.com/openai/codex/issues?q=is%3Aissue+hooks+block+approval+PreToolUse+sort%3Areactions-%2B1-desc). Reader asset: PostToolUse receipt paired with PreToolUse grant could evidence coverage gaps.

### Inferences
- The defensible slice for the reader is not "approve from phone" (free, vendor-owned) but "approval as a governed, receipted event that works when the operator is absent or is not the approver": cloud/scheduled agents, teammates/leads, and compliance. Pricing comparables are weak ($9.99-19.99/mo consumer tiers); an enterprise/team price would need to be justified by audit and policy, for which the only evidence of willingness to pay is indirect (Pushary bundling "audit trail" and "permission policies" into its $9.99 tier; enterprise managed-hook features at both vendors).
- Vendor risk: Anthropic closed the Slack-async-approval request as "not planned" and built auto mode instead, so a first-party async approver for routines is plausible but not signalled; OpenAI has left "ask" decisions and headless mobile approvals open for months without maintainer comment.

- No pricing or willingness-to-pay data for team/enterprise approval products; no case study of a company buying one.
- Whether Claude cloud sessions execute an `http` hook from committed repo settings for `PermissionRequest` was not verified (docs confirm hooks fire in cloud sessions and that repo `.claude/settings.json` is read, but do not discuss approval relays).
- Reddit, Hacker News and X threads were not reached (search budget exhausted; domains blocked), so sentiment quotes outside GitHub are missing.
