# Shared team context, rules and decision memory for AI coding tools (market notes, as of 16 Oct 2026)

Scope: products that manage/sync/version/share rules, skills, context and decisions across a team or across tools; demand evidence; decision-log tooling for agents; platform-vendor moves; adjacent paid wins. Ratings use: demand evidence strong / moderate / weak; competitive gap open / contested / closed.

Method note: GitHub star counts below were pulled live via the GitHub API on 2026-10-16. Several vendor pricing pages (mem0.ai, supermemory.ai, context7.com, cursor.com, docs.letta.com, contextstream.io, usetandem.ai, hjarni.com, forum.cursor.com) could not be fetched directly from this environment (DNS blocked), so prices come from search snippets of those pages and from third-party pricing trackers; each is marked. npm download counts could not be retrieved (registry blocked).

## Inventory: products, prices and traction (brief for (a), (c), (d), (e))

### Takeaway
The market splits into three tiers: (1) free OSS rule-sync/skills tooling with real traction but no revenue (Ruler, rulesync, claude-mem, skills repos); (2) general-purpose paid agent-memory APIs at $19–$375/month that are developer infrastructure, not team-rules products (Mem0, Zep, Letta, Supermemory); (3) a thin layer of small vendors (ContextStream, Tandem, Hjarni, BaseThread, Mneme, MemoryPlugin, Sentra) selling "shared memory for Claude Code/Cursor" over MCP at $19–$79/user/month, none with public traction figures. Platform vendors have all shipped org-level rules/skills distribution, but gated to Team/Enterprise/Business plans.

## KQ2: What specific pain do people describe that is not solved by a CLAUDE.md in the repo?

### Takeaway
Four distinct pains recur: (1) cross-repo/org drift — the same rules must live in N repos and go out of sync (one team syncs across 100+ repos via a GitHub Action); (2) adherence decay — rules are read but not followed, especially long files and incremental drift, and Anthropic's own docs say CLAUDE.md is "context, not enforced configuration"; (3) lost rationale — "why" a decision or workaround was made is not captured, so the agent re-litigates it; (4) staleness with no failure signal — "prose has no compiler". Demand evidence: strong for (1) and (2) by volume, moderate for (3), weak-to-moderate for (4).

### Cited Findings
Cross-repo / org sharing
- claude-code #14467 (open since 18 Dec 2025, `enhancement`, no Anthropic response): wants org-level CLAUDE.md from `your-org/.claude`; lists failures of duplicating per repo ("gets out of sync"), per-dev symlinks ("easy to forget"), enterprise file-based deployment ("requires an enterprise account and IT infrastructure"), submodules; top comment proposing remote `@https://` imports got 7 thumbs-up — [issue #14467](https://github.com/anthropics/claude-code/issues/14467)
- claude-code #30554 (3 Mar 2026): 2–5 person team; "company-wide standards drift as each person ends up with a different version"; onboarding requires manual copying; workaround is a private `claude-config` repo plus `setup.sh` symlinking `~/.claude/CLAUDE.md`, "fragile... requires manual git pull"; auto-closed as duplicate of #29072 and locked — [issue #30554](https://github.com/anthropics/claude-code/issues/30554)
- claude-code #29072 (URL imports in CLAUDE.md, 26 Feb 2026): user 825i "uses a GitHub Action to sync a shared CLAUDE.md across more than 100 repositories, which they describe as high-maintenance"; closed "not planned" by stale-bot 29 May 2026, no maintainer comment — [issue #29072](https://github.com/anthropics/claude-code/issues/29072)

## KQ3: Is "a curated, trigger-phrased pack of sealed decisions" something anyone asks for, or an answer in search of a question?

### Takeaway
Nobody asks for it in those words. The two halves are each asked for separately: "trigger-phrased" is exactly how vendors already route context (skill descriptions, Cursor rule descriptions/auto-attach, path-scoped `.claude/rules/`), and "sealed decisions with rationale" is the lost-rationale pain above. The combination is a plausible packaging of a known pattern rather than a demanded product; the unmet part is cross-tool, cross-repo, provenance-carrying distribution for teams too small for MDM. Demand evidence: weak (verbatim) / moderate (component pains). Competitive gap: contested on routing (vendors own it), open on sealed-decision provenance.

### Cited Findings
- Anthropic skills already use description-based triggering: "The agent is initially made aware only of the names and descriptions of each available skill" and loads details on demand — [VentureBeat quoting Mahesh Murag](https://venturebeat.com/ai/how-anthropics-skills-make-claude-faster-cheaper-and-more-consistent-for); Anthropic docs steer multi-step or partial-codebase instructions out of CLAUDE.md into "a skill or a path-scoped rule" — [code.claude.com memory docs](https://code.claude.com/docs/en/memory)
- Anthropic's org-skills launch makes admin-provisioned skills "enabled by default for all users" on Team/Enterprise, and the agentskills.io standard aims at cross-platform skills — [claude.com blog](https://claude.com/blog/organization-skills-and-directory)
- Dawiso defines "context packs" as "reusable bundles of definitions, reference data, tools, and guidance that agents can load in one step" and calls the term "an emerging pattern, not a settled standard" — [Dawiso glossary](https://www.dawiso.com/glossary/context-packs); cote-star/agent-context ships "three-layer context packs" (2 stars) — [GitHub API], [ecosyste.ms](https://awesome.ecosyste.ms/projects/github.com%2Fcote-star%2Fagent-context)

- "Sealed"/approved decisions: GitLab's decision-log widget design includes the log as context at agent plan start — [GitLab handbook](https://handbook.gitlab.com/handbook/engineering/architecture/design-documents/spec_driven_development/decision_log/); mcp-adr-analysis-server pitches "decision memory" with drift detection against code, 35 stars — [GitHub API]; sqlew pitches "team sync", 4 stars — [mcpservers.org](https://mcpservers.org/servers/sqlew-io/sqlew.git)

### Inferences
- The routing mechanism (trigger phrases → load on match) is table stakes the platform already provides for free; it is not a differentiator and should not be marketed as one.
- The differentiator, if any, is the "sealed" property: a decision with an approver, date, rationale and supersession chain, served identically to Claude Code, Cursor and Codex. No incumbent sells that; the tools that try (ADR MCP servers) have <40 stars, which can be read as either "no demand" or "nobody has done it well". The lack of any upvoted request for it tilts toward "no demand yet".
- Where the reader's asset applies: the existing pack → skills/rules/MCP pipeline maps onto pains (1) and (3) directly; the tokenizing vault maps onto the context-budget pain (AIWG 193K/200K case, Anthropic 200-line guidance). The asset does not address pain (2) adherence; pairing packs with PreToolUse hooks/deny-lists (Anthropic's recommended enforcement path) would.

## KQ4: What would a platform vendor be unlikely to build here?

### Takeaway
Vendors are converging on the same shape: org-level rules/skills, admin-provisioned, gated to paid team tiers, single-vendor, with machine-local auto memory. They are unlikely to build (a) cross-vendor distribution (Anthropic will not serve Cursor; Cursor will not serve Codex), (b) small-team distribution without IT/MDM at a sub-$20 price, (c) decision provenance with approval/supersession semantics, or (d) explicit remote URL imports (closed "not planned"). Competitive gap: closed for single-vendor org rules; open for cross-vendor sealed decisions for small teams.

### Cited Findings
- Anthropic shipped: managed CLAUDE.md via MDM/Group Policy/Ansible or `claudeMd` in managed-settings.json (cannot be excluded by users); `.claude/rules/` with symlinks; `--add-dir` instruction loading; AGENTS.md native reading; `claudeMdExcludes`; auto memory per machine — [code.claude.com memory docs](https://code.claude.com/docs/en/memory). Anthropic declined/let lapse URL imports (#29072 closed not planned by bot, no maintainer comment) and has not responded on org-level discovery (#14467) — [issue #29072](https://github.com/anthropics/claude-code/issues/29072), [issue #14467](https://github.com/anthropics/claude-code/issues/14467)
- Anthropic admin-provisioned skills: Team and Enterprise only — [claude.com blog](https://claude.com/blog/organization-skills-and-directory)
- Cursor: Team Rules via dashboard, recommend/require, Teams $40/user; MCP not team-managed yet; API for rules requested, not shipped — [forum teams-enterprise](https://forum.cursor.com/t/teams-enterprise/159194), [forum API access](https://forum.cursor.com/t/api-access-to-set-team-rules/149383)
- Copilot: org custom instructions GA for Business/Enterprise, April 2026 — [GitHub changelog](https://github.blog/changelog/2026-04-02-copilot-organization-custom-instructions-are-generally-available/)
- Codex: environment sharing Enterprise-only, admin-controlled; skills via checked-in `.agents/skills/` — [help.openai.com](https://help.openai.com/en/articles/20001545-using-codex-cloud), [danielvaughan](https://codex.danielvaughan.com/2026/05/09/codex-cli-team-configuration-dotcodex-directory-shared-profiles-repository-scoped-settings/)
- Windsurf: no admin rules distribution; repo files only — [docs.windsurf.com](https://docs.windsurf.com/windsurf/cascade/memories.md), [admin guide](https://docs.devin.ai/windsurf/plugins/guide-for-admins)
- Cross-tool is the OSS niche: Ruler (2,945 stars) and rulesync (1,524) exist precisely to fan one source to many agents — [GitHub API 2026-10-16]; agentskills.io is Anthropic's cross-platform standard for skills but not for rules/decisions — [claude.com blog](https://claude.com/blog/organization-skills-and-directory)
- Auto memory explicitly "not shared across machines or cloud environments" and a TEAMMEM flag in a community mirror is unverified — [code.claude.com memory docs](https://code.claude.com/docs/en/memory), [mintlify mirror (unofficial)](https://www.mintlify.com/killlowkey/claude-code/concepts/memory)

### Inferences
- Vendor incentives: org rules are a seat-upsell feature, so they will keep it gated and single-vendor. A cross-vendor pack server is structurally something a vendor will not build, but the OSS community already does the fan-out for free (Ruler/rulesync), so the defensible part is the content model (sealed decisions, provenance, expiry) and the hosted MCP endpoint, not the sync.
- Shared team memory in Claude Code is the most likely next vendor move (a TEAMMEM flag is rumoured in a community mirror; auto memory already classifies "decisions"); if Anthropic ships it, the single-vendor decision-memory gap closes for Claude-only teams within months. A product here must be cross-vendor or it is a feature.
- Honest conclusion on monetizable slice: the evidence supports at most a small, $10–20/user/month niche for 2–20 person teams using more than one coding agent who want approved decisions served consistently; there is no evidence yet that anyone pays for that specifically, and the free alternatives (CLAUDE.md in repo + symlinked rules + Ruler + claude-mem) are good enough for most of the complaining users. The ratings: demand strong for "agent ignores/forgets rules" (unsolvable by a context product alone), moderate for "share rules across repos/tools" (being closed by vendors + OSS), weak for "decision memory with provenance" (open gap, unproven demand).
